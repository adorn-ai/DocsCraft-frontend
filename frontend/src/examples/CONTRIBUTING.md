# Contributing to EazyETL

First off, thank you for considering contributing to EazyETL! 🎉 It's people like you that make the open source community such a fantastic place to learn, inspire, and create. We welcome contributions from everyone, regardless of their experience level.

This guide was generated by [GitCrafts](https://github.com/gitcrafts) to help you get started with contributing to EazyETL.

## Code of Conduct

By participating in this project, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md). Please read it to understand what behavior will and will not be tolerated.

## How to Contribute

There are many ways to contribute to EazyETL:

1. **Reporting bugs** or suggesting enhancements
2. **Writing code** to fix bugs or implement new features
3. **Improving documentation**
4. **Reviewing pull requests**
5. **Helping others** in the community

### Steps to Contribute

1. **Find an issue** to work on or create a new one
   - Check the [existing issues](https://github.com/username/eazyetl/issues) for something to work on
   - If you have a new idea, create an issue first to discuss it with the maintainers

2. **Fork the repository**
   - Click the "Fork" button on the top right of the [repository page](https://github.com/username/eazyetl)

3. **Clone your fork**
   ```bash
   git clone https://github.com/your-username/eazyetl.git
   cd eazyetl
   ```

4. **Set up your development environment** (see below)

5. **Create a branch** for your changes
   ```bash
   git checkout -b your-feature-branch
   ```

6. **Make your changes** and commit them (see commit message guidelines below)

7. **Push your changes** to your fork
   ```bash
   git push origin your-feature-branch
   ```

8. **Open a pull request** (see pull request process below)

## Setting Up Development Environment

### Prerequisites

- Python 3.8 or higher
- pip
- [Poetry](https://python-poetry.org/) (for dependency management)

### Installation

1. Install Poetry (if you haven't already):
   ```bash
   curl -sSL https://install.python-poetry.org | python3 -
   ```

2. Install project dependencies:
   ```bash
   poetry install
   ```

3. Activate the virtual environment:
   ```bash
   poetry shell
   ```

### Running Tests

We use `pytest` for testing. To run the tests:
```bash
pytest
```

### Running Linters

We use several linters to maintain code quality:
```bash
# Run all linters
make lint

# Or run them individually
black .
flake8 eazyetl
isort eazyetl
mypy eazyetl
```

## Coding Standards

To maintain consistency across the codebase, please follow these guidelines:

1. **Code Style**:
   - Follow [PEP 8](https://peps.python.org/pep-0008/) style guide
   - Use 4 spaces for indentation
   - Maximum line length is 88 characters
   - Use descriptive variable and function names

2. **Type Hints**:
   - Use Python type hints for all public functions and methods
   - Run `mypy` to check type hints

3. **Docstrings**:
   - Follow [Google style docstrings](https://google.github.io/styleguide/pyguide.html#38-comments-and-docstrings)
   - Include docstrings for all public modules, functions, classes, and methods

4. **Imports**:
   - Group imports in this order: standard library, third-party, local
   - Use absolute imports
   - Sort imports alphabetically within each group

5. **Testing**:
   - Write tests for new features and bug fixes
   - Aim for at least 80% test coverage
   - Use pytest for testing

## Commit Message Guidelines

We follow the [Conventional Commits](https://www.conventionalcommits.org/) specification for commit messages:

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

**Types**:
- `feat`: A new feature
- `fix`: A bug fix
- `docs`: Documentation only changes
- `style`: Changes that do not affect the meaning of the code (white-space, formatting, etc)
- `refactor`: A code change that neither fixes a bug nor adds a feature
- `perf`: A code change that improves performance
- `test`: Adding missing tests or correcting existing tests
- `chore`: Changes to the build process or auxiliary tools and libraries

**Examples**:
```
feat: add new extractor for CSV files
fix(load): handle connection errors gracefully
docs: update README with installation instructions
```

## Pull Request Process

1. **Before submitting**:
   - Ensure your code follows the coding standards
   - Run all tests and linters
   - Update documentation if needed
   - Keep your pull request focused on one change

2. **Submitting a pull request**:
   - Go to the [pull requests page](https://github.com/username/eazyetl/pulls)
   - Click "New pull request"
   - Select your fork and branch as the compare branch
   - Fill in the pull request template
   - Click "Create pull request"

3. **After submitting**:
   - Wait for a maintainer to review your pull request
   - Be prepared to make changes based on feedback
   - Once approved, a maintainer will merge your pull request

## Issue Reporting Guidelines

When reporting issues, please include as much information as possible:

1. **Bug reports**:
   - Steps to reproduce the bug
   - Expected behavior
   - Actual behavior
   - Environment details (OS, Python version, etc.)
   - Relevant logs or error messages

2. **Feature requests**:
   - Detailed description of the feature
   - Use cases for the feature
   - Potential implementation ideas

3. **General guidelines**:
   - Check if the issue has already been reported
   - Be clear and concise in your description
   - Include code samples if relevant
